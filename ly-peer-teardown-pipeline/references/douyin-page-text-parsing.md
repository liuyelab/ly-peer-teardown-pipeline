# 抖音视频原始页面文本解析

## 文件来源
`同行素材库/{账号}/原始资料/重点视频原始页面文本/` 下有两种已实测命名变体：
- 变体A：`NN_{视频ID}.txt`，标题行带 `TITLE: ` 前缀（博主A等早期抓取）
- 变体B：`{账号}-重点视频-R{NN}-{主题}-页面文本.txt`，**无 TITLE: 前缀**，标题行裸出现在章节要点之后/发布时间之前（博主B 2026-07 抓取）
解析前先 ls 目录确认变体，正则锚点按变体二选一。

## 锚点与正则
- **标题**：变体A 用 `TITLE: (.+)`；变体B 无前缀，取「章节要点块之后 / 发布时间之前」的裸标题行（含 #话题标签，可作话题参考）
- **章节要点**：`章节要点` 到 `内容由AI生成` 之间（无「共N个」计数也可）。**容错变体**：部分文件无 `内容由AI生成` 结尾标记（如抓取失败或AI未生成摘要），用 `章节要点(.*?)(?:\d{2}:\d{2}|第\d+集|全部评论)` 截断。正文为「时间码 + 小节标题 + 说明」结构：
  - 提取时删掉 `\d{2}:\d{2}` 时间码行
  - 每节第一行是小节标题，后面是说明文字（AI生成的视频要点总结，可信）
- **互动数据**（关键顺序）：标题行之后紧跟 4 个数字 = 赞/评论/收藏/分享：
  ```
  {标题行（含话题标签）}
  {赞}
  {评论}
  {收藏}
  {分享}
  ```
  示例：`11.5万  2114  8.3万  4.8万` = 赞11.5万 · 评论2114 · 收藏8.3万 · 分享4.8万
  注意：顺序是 赞/评论/收藏/分享，不是赞/收藏/评论——初次解析容易搞反。
  **可靠锚点**：`t.find('发布时间：')` 再往前取 ~160 字符，必含标题行+4数字，两条变体都适用。**不要用 `find('举报')` 当锚点**——页脚 ICP 备案区也含「举报」字样，会截到导航噪音（实测踩坑）。
- **发布时间**：`发布时间：(\d{4}-\d{2}-\d{2} \d{2}:\d{2})`
- **评论区**：`全部评论` 之后。评论块格式：`{昵称}\n...评论正文...\n{赞数}\n\n分享\n回复`。`作者赞过` 标记作者亲自认可的评论（高价值金句候选）。
- **抓取失败特征**：文件只有导航噪音 +「视频数据加载中」→ 无标题无数据，回退到研究报告的「重点视频详情表」补要点。

## 数据源层级（先统计后页面，别搞反）
`原始资料（不用看）\` 下通常有多个数据文件，权威性从低到高：
- **统计与前20%筛选.json**：标题 + 点赞估值 + 题材初判 + 热度排名。**先读它挑出前20%重点作品**，再决定读哪些页面文本（77条作品不用全读页面，只读重点条的）
- **原始列表.json / 作品总表.csv**：全部作品的标题 + 点赞显示（比估值略准），无收藏/评论/分享
- **重点视频原始页面文本/*.txt**：唯一有真实 收藏/评论/分享 的来源；互动数据以页面文本为准，与统计JSON的点赞估值交叉核对
- **原始可核验数据.json**：账号级信息（粉丝/获赞/简介/跨平台账号），做素材库头部和红线背景用

## 提取效率技巧
页面文本含大量噪音（导航栏/推荐视频列表/ICP备案/搜索热词），**不要全文打印进上下文**。用 python 脚本按锚点切片：
```python
import re
t = open(f, encoding='utf-8', errors='replace').read()
title = re.search(r'TITLE: (.+)', t)
# 章节要点
m = re.search(r'章节要点\n(.*?)\n内容由AI生成', t, re.S)
# 互动数据
data = re.search(r'内容由AI生成\n.+?\n(\d+(?:\.\d+)?万?)\n(\d+)\n(\d+(?:\.\d+)?万?)\n(\d+(?:\.\d+)?万?)', t, re.S)
```
批量处理：一次脚本循环全部文件，只打印标题+数据+要点前500字。

## read_file 误判 binary 的绕过
中文 UTF-8 文本文件可能被 read_file 判为 binary（`is_binary: true`）无法显示，即使内容完全正常。**不要建临时转码文件**（实测照样被误判）。直接 terminal python：
```bash
python -c "
data = open('文件.md','rb').read()
t = data.decode('utf-8')
lines = t.split('\n')
for i,l in enumerate(lines[30:80], start=31): print(l)
"
```
分页切片打印（先 `print(len(lines))` 探总数）。

## 素材点去重规则
- 同主题（如多个数字口诀视频）只留数据最强一条（按赞数），弱条要点并入强条「怎么套」里并注明来源
- 数据弱但句式独特/口号强（如「先拍100条视频再说」17赞）可保留，注明「数据弱仅作结构参考」
- 收藏率 = 收藏 ÷ 赞：教程/口诀型内容 60%+ 是强信号，写进「数据说明」作为该素材的质量证据

## 素材库格式结构（本文件内嵌，直接照此）
- 头部：用途说明 + 格式说明（每点=内容+来源+怎么套+已用[ ]）+ 蒸馏卡指针 + 作品数/日期 + 去重声明
- 检索索引表：`| 想做什么内容 | 去哪个区找 | 最强素材点 |`（10行左右）
- A 标题素材（≈7点）：`### A-001 句式型名 已用[ ]` + 原例/来源（视频名·赞·收藏）/怎么套/数据说明
- B 开场钩子（≈4点）：做法/来源/为什么有效/怎么套
- C 观点金句（≈10点）：金句（引号原文）/来源/用法（讲什么时引用）；同主题金句合并，数据取强条
- D 案例素材（≈6点）：来源/用法/注意（不可复制性、反噬风险、可匿名化）
- E 结构模板（≈8点）：内容（执行清单逐条）/来源/用法
- 红线区：编号列表（≥6条），含版权、标来源、身份背景、别学项、竞品预警、数据时效
- 文末：`*建立：{日期}。素材来源：N条作品原始页面文本（章节要点+互动数据+评论区）+ 完整同行研究报告。格式对齐本文件所述格式。*`

## 实测案例
### 案例1（博主A，2026-08）
- 15 条作品 → 36 个素材点（A7/B4/C11/D6/E8），收藏率 62%-79% 全部达标
- 最强素材：中间商五步（4.9万赞·3.4万收藏·1.3万分享）；评论区「情绪需求论」3470 赞（作者赞过）> 博主第二强正片 2617 赞
- 竞品预警写法示例：「他公开要做 WorkBuddy 教程——别照抄他的定位（搭工作台/工具层），你主打 Codex+WorkBuddy 做真实项目（结果层）」

### 案例2（博主B，2026-07 抓取 / 2026-08 拆解）
- 77 条作品（量最大）→ 40 个素材点（A9/B5/C10/D9/E7），只拆前20%重点16条+少数高相关普通条（如「5分钟搞定为啥报课」8524赞）
- 文件为变体B 命名（无 TITLE: 前缀），互动数据锚点用 `发布时间：` 前160字符
- 数据规律直接写进素材点数据说明：机会型内容收藏爆炸（R02 机会型 8.3万收藏≈赞的72%、R03 工具型 6.5万≈80%）；情绪故事型评论/分享强收藏弱（R01 情绪故事 12.1万赞但收藏仅7322、分享3.2万）
- 红线区写法示例：把博主实际被评论区拆台的坑写实（如宣传口径与实际不符被质疑、标题承诺的内容正文没兑现、导流话术被骂"只想让人付费"），提醒自己别踩
- 素材点数控制：任务要求 30-40 个，A≈9/B≈5/C≈10/D≈9/E≈7 是77条大账号的合理分布
